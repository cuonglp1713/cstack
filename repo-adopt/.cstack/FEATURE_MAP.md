# Product feature map

This is a partial index of user journeys discovered while working in an existing repository. It does not claim to cover every feature. Add or update the relevant journey for the current task; do not inventory unrelated areas as a prerequisite.

| User journey | Delivery | Verification evidence | Entry point and action | Owning code | Spec record or detail |
|---|---|---|---|---|---|

Delivery is `planned`, `in_progress`, or `implemented`, based on the current contract and code. Verification evidence names a check actually observed, with its environment and result, or says `not checked in this work`. An existing test or CI workflow may be listed as a path to check but is not a passed result by itself.

Inspect code, routes, UI, tests, and existing docs before recording an entry point or implementation status. Link the actual spec for work and proof when one exists; put longer journey detail in `.cstack/docs/features/` when useful. Leave uninspected journeys unmapped and update affected rows when behavior or proof paths change.
