# Product feature map

This map belongs to this repository and describes its user journeys. Draft planned journeys from agreed product goals and discover implemented paths from code, routes, UI, and tests. Validate the actual path and observable result before marking it verified; do not invent screens, routes, selectors, or commands.

| User journey | Status | Entry point and action | Owning code | Observable proof | Spec record or detail |
|---|---|---|---|---|---|

Status is `planned`, `implemented`, or `verified`. A new empty repo has no implemented or verified row; add planned rows only after the product idea is known. For a web app, record navigation and stable selectors; for an API, method/path and authentication; for a CLI, command and changed output; for background work, how the user starts it and sees completion.

Keep this file a short index. Link the relevant actual spec for work and proof, and put lengthy journey steps in `.cstack/docs/features/` when needed. Update affected rows when entry points, code ownership, or proof paths change. An existing test file alone is not observed proof.
